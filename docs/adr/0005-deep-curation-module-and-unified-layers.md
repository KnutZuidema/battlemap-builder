# Deep curation module with unified layers and strict invariants

Candidate curation and rejection transitions are orchestrated by a deep, asynchronous domain module (`CurationService`) implementing narrow persistence seams (`CurationStore` and the `CurationWorkflow` port), replacing fragmented route orchestration and eliminating circular full-store manifest scans. The lifecycle unifies `CandidateLayer` and `CuratedLayer` into a single canonical `Layer` struct, collapses legacy themes into dynamic `Tag` collections with transparent serde migration, strictly requires exactly one `Ground` layer, delegates map-level vision calls to a decoupled `DescriptionService` with no silent fallbacks, and strips synthetic caption mutation from storage read paths. Map-level physical descriptions stay strict (`503` when unconfigured, `502` on upstream failure or empty output, no procedural fallback), while per-16×16-section captions are best-effort: each section independently falls back to the deterministic `CaptionGenerator` when its vision call fails or its crop is unavailable, so curation and regridding of multi-section maps still complete.
