# Grid-aligned 16×16 map sections and dynamic LoRA export

Curated Maps persist an explicit integer Grid Configuration (`cell_size_px`, `offset_x`, `offset_y` normalized to `[0, cell_size_px)`) and must span at least `16×16` full Grid Cells on their Ground layer. Instead of writing letterboxed `<id>_lora1024.png` and `<id>_lora1024.txt` files to disk—which distorted spatial scale across maps of different grid dimensions and baked `#0b0f17` padding bars into training data—curation partitions the map's full-grid lattice into evenly spaced `16×16` Grid Cell Map Sections (`kx = ceil(Cols / 16)`, `ky = ceil(Rows / 16)`) and caches a vision-generated Physical Description per Map Section in `manifest.json`. Both `ReferenceProvider` few-shot conditioning and LoRA dataset ZIP export (`{theme}/{id}_c{col}_r{row}_lora1024.{png,txt}`) dynamically crop and Lanczos3-resample these exact `16×16` Map Sections on demand, guaranteeing a uniform `64px = 1 Grid Cell` (`5ft`) scale with zero padding bars or redundant disk artifacts.

Cropping is exact: a Map Section is only resolvable when its full `16 * cell_size_px` box fits inside the loaded Ground layer image. An out-of-bounds section is never center-cropped, magnified, or otherwise rescaled — `ReferenceProvider` treats the reference as unresolved and falls back to the static reference image, and the LoRA ZIP export logs a warning and skips that section.

Every exported caption is the `Trigger Phrase` followed by the sample's `Physical Description` — its own cached section description, otherwise the map-level one. The phrase is applied exactly once, at caption generation, and is never persisted inside a `Physical Description`: a Map Section whose crop description fails or whose crop is unresolvable reuses the map-level `Physical Description` rather than synthesizing a caption, so perspective and art style stay renderer-owned (ADR-0002). `GET /api/dataset/readiness` audits the store against this same contract — readable Ground layer, a full `16×16` Grid Cell window, resolvable section boxes, and a non-empty perspective-neutral `Physical Description` per section — so a `Training Dataset` is never handed to a `Training Run` unverified.
